# Audit, October 2026: what was found, fixed and left

Three reviews (server C#, browser JavaScript, SQL / configuration / layout / offline use). Each finding was checked against the code; the fixed
ones were re-tested in a real browser (Chromium) or with a small test program. The first audit (history) is `AUDIT.md`.

## Offline use
No outside address is used anywhere: the only `http(s)://` strings are XML namespace names in `xlsx-lite.js` (never requested) and a comment link in
`Web.config`. Fonts are local. The Content-Security-Policy (`default-src 'self'`) blocks any outside load. A browser run over the login page, the
estimator (all steps, Masters, Print) and the report at six screen sizes made **no request to any other host**.

## Fixed

## Added later: recalculation with the current masters

- `recalcProject` (admins): replaces the saved estimate and the cost figures of an entry awaiting verification or verified; the version token (`updated`) must match, the workflow, submitter and verifier stay, and the history gets a `recalc` line with the old and new cost written by the server.
  Script `02` widens the history check for it (safe to run again).
- This **can change figures of verified entries** (and therefore reports and year totals). Refused for sent-back entries and for verified entries whose value was adjusted by the verifier.
- Per-estimate overrides of rates, loadings and AMC % go back to the masters; benefit rates are reset only on request.

## Known and left (judgement calls or larger changes)

- **No individual identity.** With one shared password the name is whatever is typed: "only the submitter can edit" and "a different admin must verify" cannot
  be enforced (`AllowSelfVerification=true`), and the log shows typed names. Per-user sign-in is the only real fix.
- The shared password is stored as an unsalted SHA-256 in `Web.config`; it is a short password. Use a long one and restrict who can read the file.
- Enhancement records take only the change-request days as their value (`baseValue`); unclear whether intended.
- Unticking "contingency, overheads, mark-up or GST" keeps any values typed while it was ticked.
- Quotation numbers always end in `-01`; the print preview of a verified entry uses the numbers it had when selected.
- An entry opened for edit or copy replaces the draft without asking.
- Drafts and masters in the browser are not kept per user.
- Saving a master is last-write-wins; bad numbers in a master save become 0 or the maximum instead of an error.
- The register list loads every estimate's JSON (about 0.8 MB for 190 entries, growing).
- Deleting an entry also deletes its history; nothing records who deleted it.
- Re-registering a project that script `07` imported makes a second row; the report totals then count both.
- One row per typed name in `dbo.SwAppUser`; `RegisterId` keeps only letters, digits, `_` and `-` of the name, so `john.doe` and `johndoe` collide.
- Excel reader: no zip-bomb or ZIP64 limits, dates stored as serial numbers come back as numbers.
- Logout is a plain link (another site could sign a user out).
- `dbClassSql` (your class): one shared connection (requests take turns), a broken connection state is not reopened until the pool recycles, and a write
  failure is only a `false`. Not changed.
