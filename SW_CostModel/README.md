# Central Automation: estimate and quotation

Estimator for software projects (Masters, Registration, Approval, Print), an Excel upload page, and a report with
Central Automation cost against a software-company benchmark, and the value each project
creates. Runs on Windows IIS with SQL Server, with no internet access needed on the server or
the client.

## Quick start

1. Create the IIS application pool, then run `database\01` to `03` (and `07` for the project list) in SSMS.
2. Copy `Content`, `Scripts`, `Standards`, `fonts` into the project root, build and publish from Visual Studio,
   create an IIS site on a .NET 4 Integrated application pool: Anonymous enabled, Windows Authentication off.
3. Set `CCCConString` in `Web.config` on the server.
4. Open the site: the login page takes any name and the password set in `Web.config`.

Full steps and troubleshooting: [docs/DEPLOYMENT_IIS.md](docs/DEPLOYMENT_IIS.md).

## How it fits together

- The estimator calls `api/estimator.ashx`. The API reads the masters from the master tables, stores each submitted estimate in
  `dbo.SwProjectRegister` (with the full estimate as JSON, so it can be reopened and printed later), and the approval history in
  `dbo.SwProjectLog`. All database access goes through `dbClassSql`.
- One shared password (login page `Default.aspx`, checked by `LoginModule`); anyone who signs in is an admin.
- Nothing is loaded from the internet: fonts, scripts, styles and the login page's libraries are files on the server.
- The layout is fluid, from a phone to a 2560px monitor. The quotation prints on A4.

## Who sees what

Everyone who signs in is an admin: costs, rates, loadings, ROI and payback; Approval for everyone's entries; verify or send back an entry
(including their own: `AllowSelfVerification`); Masters, Excel upload, Print / quotation, and the report. The name typed at the login page is
recorded as who submitted and approved. The server still withholds costs from a non-admin account, which matters if the site is later
changed to per-user sign-in.

## Changing the masters

An estimate keeps a copy of the rates it was made with, so saving a master only affects new estimates. An admin applies new rates to existing entries with
**Approval > Recalculate with the current masters** (preview first; one entry or all entries awaiting verification and/or verified, per financial year) and, for the
estimate on screen, **Registration > Use the current masters**. Team, sizing, quantities, benefits, the charged amount and the quotation details are kept; rates, prices,
loadings and AMC % come from the masters. Every change is written to the entry's history. Entries sent back to the submitter, verified entries whose value was adjusted, and
entries without a saved estimate are not touched. Details: `docs/DEPLOYMENT_IIS.md`.

## Value creation

The Value creation step records what a project gives back: man-hours saved, downtime
avoided, energy, quality, material and so on. Each line is quantity × ₹ per unit, per year or
one-time. Choosing a benefit fills in its usual unit and value from the Value creation master
(admins set these on the Masters page). Admins also see the value against the Central
Automation cost: value over the years of ownership, return on cost and payback. Verified
value is totalled by financial year on the Approval page and in `dbo.vw_SwYearlySummary`.

## Dashboard

**Dashboard** in the menu (`project_dashboard.aspx`, admins) shows the register as a deck of five slides: **Summary**, **Money** (in-house against the
software-company benchmark by financial year, project type and department), **Effort / FTE** (1 FTE = 2,740 hours), **Value** (value a year, return and
payback) and the **project list** with a PDF of each estimate.

- **Choose the projects**: a date range (*From* / *To*: projects running at any time in the period, by their start and end dates; presets *This financial year*,
  *Last 12 months*, *All dates*), *Include projects without dates*, *Verified only*, and **Projects**: a searchable list with tick boxes (none ticked = all that match).
- The choice is kept in the address (copy the link to share the same view) and in the browser for the next visit.
- **Previous / Next**, the arrow keys or the slide strip move between slides; **Present** shows the slide full screen; **Print** gives one slide per landscape page
  (choose *Save as PDF* in the print dialog for a file).
- Figures are the recorded values of each entry, the same as the Approval totals and the report.

**Visual slides for meetings.** The deck opens with five infographic slides: **Working principle**, **Benefits at a glance**, **Money**, **FTE** and
**Productivity**. Costs, cost avoided (by live / in-progress projects and by Business KPI) and project counts come from the register and follow the choice
above; the stated figures (TAT examples, task reductions, man-hours, output, potential) are the **highlights**: **Edit highlights** opens a panel where an
admin changes them (rows can be added, removed and moved; opening a section shows its slide) and **Save** keeps them for everyone (`dbo.SwDashboardContent`,
each save copied to `dbo.SwMasterAudit` as `dash`). **Download PNG** saves the slide on screen as a 1920 x 1080 picture to paste into PowerPoint;
**All slides as PNG** saves every slide but the project list. The header photos are files in `web/assets/img` (jpg / png / webp): put new ones there and choose
them under *Look* in the editor.

Project dates: **Start date** and **End date** on the Registration Basics step (empty end = still running), two optional last columns in the Excel template and the CSV,
and `database\08_project_dates.sql` for the imported project list.

## The project sheet (Excel upload or CSV import)

The team fills **one Excel sheet, one row per project**: project details, a team head-count
(and its usual level), server size, and up to three benefits with a quantity per year. No
prices, no role-by-role breakdown, no explanations.

1. An admin downloads the blank template from the **Excel upload** page (`project_upload.aspx`) (its drop-down lists come from
   the current masters), or takes `database\templates\projects-template.xlsx`.
2. The team fills it and sends it back; one file can hold many projects.
3. Load it either way:
   - **Excel upload** page: every project's cost, total against the benchmark, value per year
     and payback show at once, with any unreadable answers listed by line. A project that
     repeats another in the file, or that is already verified in the register, is flagged and
     not sent. Submit one or all, open one in the estimator, or download a cost summary.
   - **Straight into SQL Server**: save the sheet as CSV and run
     `database\05_import_projects_csv.sql`. It checks every value, imports nothing if
     anything is wrong, and adds the projects as entries awaiting an admin's costing and
     verification.

Both give the same costs.
Uploads on the page are kept until the page is closed; submit them to keep them. Columns and
allowed values: [docs/PROJECT_SHEET.md](docs/PROJECT_SHEET.md).
